# Patches to the pinned EKA2L1 source

Applied, with `git apply --check`, to upstream `e04eb030653d185483a44f0394d42a319ad334f2` before compiling. The resulting version is suffixed `+jgo-vpl1`. EKA2L1 stays in its separate optional container; no firmware is included.

- `0001-control-install-vpl-factory-firmware.patch` exposes the desktop `eka2l1::install_firmware` routine through `POST /v1/devices` with `{ vpl, variant?, boot?, isolateDrives? }`. It advertises `firmwareFormats: [rom, rpkg, archive, vpl]` in `/v1/capabilities`, uses the existing async jobs/progress, requires an explicit zero-based variant when there is more than one (an absent `variant` is detected with `contains()` before it is read: the non-const `operator[]` of `control::json` inserts a null member, which previously made every request without `variant` fail with `bad_request`; found by `vpl-real-smoke.mjs` against the real binary), and reports VPL/FPSX errors. The patch also fixes the existing variant loop (a matched index previously remained unchanged and could select a later variant) and refuses missing, non-regular or escaping component paths. VPL XML is limited to 4 MB.
- `0002-reject-invalid-fpsx-headers.patch` fixes the impossible magic-range condition and bounds the header and TLV count before allocating metadata from an uploaded FPSX file. The real FPSX parser/extractor remains upstream's implementation.

The C++ modifications are derivatives of the respective upstream files and retain their upstream licensing (Control API: GPL-2.0-or-later; firmware/FPSX sources: GPL-3.0-or-later). They are distributed as source patches, not linked into the MIT JGO process.

`tests/scripts/vpl-real-smoke.mjs`, run by `.github/workflows/symbian.yml`, exercises the **real** patched binary using synthetic manifests and deliberately invalid image bytes: invalid XML, explicit/ambiguous variants, corrupt FPSX, and missing/unsafe filenames. It must not install any device. The test involving a successful factory installation in `tests/integration/symbian.test.ts` and `tests/e2e/symbian.mjs` uses the clearly labelled fake emulator and verifies JGO's transport/UI only. A successful extraction of a genuine factory kit requires the operator's firmware and remains a manual test.
