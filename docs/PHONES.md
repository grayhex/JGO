# Телефоны и подготовка к тестированию EKA2L1

Изменения рассчитаны на экспериментальное ядро из PR #35 (`feat/eka2l1-symbian`). Java ME продолжает исполняться в KEmulator; Symbian и оба поколения N-Gage — в отдельной службе EKA2L1. Наличие скина **не устанавливает прошивку** и не доказывает запуск настоящей игры.

## Независимые сущности

| Сущность | Источник | Ответственность |
|---|---|---|
| `PhoneSkin` | `packages/protocol/src/phoneSkins.ts`, `/phones/<id>/config.json` | Корпус, два вида, дисплей, кнопки и координаты. Без ОС и firmware. |
| `EmulatedDevice` | `packages/protocol/src/emulatedDevices.ts` | Engine, ОС, разрешение, раскладка, реальный Java preset или product code прошивки EKA2L1. |
| `GamePlatform` | `packages/protocol/src/platforms.ts` | `j2me`, `symbian`, `ngage`, `ngage2`. Совместимые алиасы `Platform` / `PLATFORMS` для протокола ядра #35. |

Отдельная связь `PHONE_COMPATIBILITY` позволяет одному скину обслуживать несколько платформ. Java-профили с одинаковыми preset и раскладкой переиспользуются. `PHONE_PROFILES` / `resolvePhone` остаются совместимым Java ME API; «exact» означает точный Java-пресет, а не наличие Symbian ROM.

Платформа принадлежит **игре** (`GameMeta.platform`), определяется форматом пакета и не меняется при выборе картинки. Старые игры без `platform` остаются `j2me`. `GameSettings.emulatedDeviceId` — необязательный профиль из каталога; `symbianDevice` — реальный код установленной прошивки из ядра #35. Сброс `emulatedDeviceId: null` возвращает выбор по реальной прошивке. SQLite и пути существующих RMS не меняются.

## Мои телефоны

Из каталога (15 телефонов) пользователь выбирает нужные — в мастере первого запуска и в *Settings → My phones* (`settings.myPhones`). Нужен минимум один телефон для каждого вида игр: Java ME, Symbian S60 и N-Gage; для каждого вида задаётся телефон по умолчанию (`phone.skinId` для Java ME, `nativePhones.symbian|ngage|ngage2`). Страница Phones по умолчанию показывает только выбранные телефоны (переключатель «Show only my phones»). Платформы везде показаны картинками набора MGO, а не словами. В плеере при открытии игры другого вида телефон меняется на подходящий; если текущий тоже подходит, но на другом картинка лучше (Java ME: экран совпадает с тем, под который сделана игра; Symbian/N-Gage: экран больше, прошивка установлена), показывается подсказка с кнопкой «Switch to …» — сам по себе рабочий телефон не меняется.

N8 не объявляется S60 5th Edition или N-Gage 2.0. E71 не объявляется официальным N-Gage 2.0 устройством. Совпадение ОС или разрешения не доказывает совместимость. Другие региональные product codes можно выбирать непосредственно из установленных устройств; если код не входит в каталог, модель/ОС явно помечаются непроверенными, без выдуманного профиля.

Для Classic/QD Java ME используется реальный `176x208-nokia-full-screen`, который в `presets.xml` идентифицирован как **Nokia N70**. UI и references явно называют этот fallback; строка `microedition.platform` остаётся `NokiaN70`, без вымышленного N-Gage firmware. Для N70 это точный Java preset. Остальные новые модели используют существующие generic-пресеты без подмены `MIDPPlatform`.

## Проверка готовности

`GET /api/phones` возвращает каталог устройств, связь совместимости и доступность по настоящим Java-пресетам/установленным firmware. `GET /api/games/:id/phone` возвращает `SymbianStatus` и `NativePhonePlan` для нативной игры. Оба маршрута используют обычную авторизацию MGO. Каталог работает и без KEmulator.

Проверка `nativePhonePlan` отделяет службу от прошивки и изображения:

1. Служба не настроена или недоступна — запуск заблокирован, доступны обновление статуса, управление прошивками и диагностика.
2. Нет прошивки — скин не подменяет её. Установите firmware в Settings → Symbian.
3. Выбор: устройство игры / явного профиля → умолчание платформы → единственное установленное устройство. При нескольких устройствах без выбора — `device_required`; отсутствующий код — `device_missing`.
4. Явный профиль EKA2L1 обязан соответствовать выбранному product code и платформе. Иначе `firmware_mismatch` или `incompatible_profile`. Выбор по одному размеру экрана не используется.
5. Для неизвестного каталогу кода прошивки выводится предупреждение о непроверенной модели/ОС. Запуск явно выбранной пользовательской прошивки остаётся возможным для экспериментального теста.
6. Служба занята внешним экземпляром/firmware job — новый запуск заблокирован. Замена собственной сессии MGO остаётся возможной.

Сервер повторяет проверку **до остановки другой игры, создания каталогов сохранений и запуска процесса**. UI не является единственным ограничителем. Адаптер дополнительно повторяет выбор перед boot. Изменения состояния между проверками могут привести к отказу запуска; он не вызывает fallback в KEmulator.

В плеере видны платформа, версия EKA2L1, реальный код прошивки, источник выбора, ОС/раскладка известного профиля и статус первого кадра. Во время долгой установки плеер подключается к starting-сессии и показывает её журнал; Stop доступен после появления сессии. Перезапуск не меняет ядро. Отсутствие Java runtime не блокирует карточки и запуск нативных игр. Java-опции, heap, JSR-75 и speed не показываются для EKA2L1.

Скин можно выбрать независимо. Для нативной игры `/phones` сохраняет только `skinId`, а не `symbianDevice`/ROM. Кнопка «Use matching skin» предлагает корпус по фактически выбранной firmware. Для новой нативной игры подходящий известный скин подбирается один раз; пользовательский выбор сохраняется. Пропорции framebuffer сохраняются с letterbox независимо от корпуса. Поворот нативной картинки не переключает на другую прошивку или E71.

## Интерфейс тестировщика

- Библиотека: отдельный сохраняемый фильтр Java ME / Symbian / N-Gage / N-Gage 2.0; поиск, жанры и сортировка работают вместе с ним.
- Прошивки: [заводские VPL + FPSX](FACTORY_FIRMWARE.md) через настоящий десктопный установщик без предварительного дампа, выбор варианта и сохранение исходных имён; прогресс отправки файла, отмена до установки, предварительная проверка лимита, блокировка повторной отправки. Установка идёт отдельным job; отмена отправки не выдаётся за отмену уже начавшегося job.
- Наблюдение за job переживает перезагрузку страницы: сохраняется только ID задания. При разрыве мониторинга видна ошибка и кнопка возобновления без повторной установки.
- Статус службы обновляется в плеере последовательно, без наложения долгих запросов. После смены профиля старое «готово» не используется. Есть ручное обновление и диагностика.
- Нативный pointer поддерживает восемь независимых контактов, инверсию поворота, освобождение при cancel/blur/смене вида. Клавиатура и gamepad используют прежний InputController и общий held-state.

## Графика и расширение каталога

15 комплектов графики используют общий PhoneSkin renderer: корпус с прозрачным LCD, lossless PNG/WebP, измеренные полигоны клавиш, общий input и адаптивное масштабирование. Classic/QD имеют горизонтальный корпус, но вертикальный экран **11:13**. Их zoom использует `zoomCrop` по обеим осям; прежние вертикальные модели сохраняют `zoomBottom`. N8 имеет одну Menu/Home без вымышленного J2ME-кода; внешний keypad доступен в обоих видах. Для N8 добавлен screen close-up, поведение прежних 5800/S5230 сохранено.

Источники, хеши просмотренных фотографий и ограничения достоверности — в `/phones/<id>/references.md`. Исходные image_gen-иллюстрации, инструкция, измерения и контур сохраняются в `design/phones/<id>/`. Все новые корпуса имеют `review-draft`, как прежние: точная геометрия LCD и отсутствие перекрытий не заменяют историческую приёмку маленьких легенд.

Добавление модели: ID в `PHONE_SKIN_IDS` → исходник/измерения/references → `export_measured.py <id>` → реальный Java preset с явным fallback → профиль/связь `PHONE_COMPATIBILITY`. Нативная доступность всегда приходит от службы, а не из конфига рисунка. Для новой региональной firmware добавьте отдельный проверенный product code; не сопоставляйте прошивки по похожим именам и разрешению.

## Проверки

```bash
npm run typecheck
npm run build
npm test
npm run test:phones
npm run test:integration
CHROMIUM_PATH=/path/to/chromium node tests/e2e/phone-expansion.mjs
CHROMIUM_PATH=/path/to/chromium node tests/e2e/symbian.mjs
```

Java-тесты используют настоящий KEmulator. Symbian end-to-end использует настоящий агент и **поддельный** EKA2L1 из fixture: проверяет UI/HTTP/WebSocket, firmware jobs, выбор и предупреждения, ввод и кадры, а не настоящую игру. Для настоящего ядра/дампа выполните [SYMBIAN_TESTING.md](SYMBIAN_TESTING.md), сохраните диагностику и результаты в [NATIVE_TEST_MATRIX.md](NATIVE_TEST_MATRIX.md).
