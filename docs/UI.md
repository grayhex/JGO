# Интерфейс: Command Center, PhoneSkin, /phones

Веб-интерфейс (`apps/web`) построен по дизайн-системе «Evreghen Command Center»: тёплый светлый рабочий фон, полупрозрачная тёмная
оболочка (sidebar + header, blur 12 px), единственный акцент — оранжевый `#fe6e00`, статусные бейджи, тёмная тема (`light` / `dark` / `auto`,
переключатель в шапке, выбор хранится в браузере). Токены — в `apps/web/src/styles/tokens.css`, остальное разложено по файлам
`base / ui / shell / library / skin / player / phones`.

![player](img/player.png)

## Экраны

| Маршрут | Что это |
|---|---|
| `/` | библиотека: карточки игр, поиск в шапке, фильтры All / Favorites / Recent, drag-and-drop загрузка JAR/JAD |
| `/play/:id` | плеер: телефон с живым экраном, панели управления эмулятором |
| `/phones` | «Phone lab»: проверочная страница всех пяти моделей в обоих видах |

Плеер: слева «сцена» (телефон, переключатель **Phone / Screen**, полный экран, выбор из пяти моделей, внешние софт-клавиши и клавиатура),
справа панели **Session**, **Emulation profile** (пресет устройства KEmulator, разрешение, раскладка клавиш, heap, «сохранить как умолчания игры»),
**Display**, **Controls**, **Audio**, **Telemetry** (FPS, задержка, ресурсы, sparkline-графики), **Compatibility** (анализ JAR) и **Emulator log**.

## PhoneSkin

Компонент `apps/web/src/skin/PhoneSkin.tsx` рисует телефон по `public/phones/<id>/config.json`:

```
LCD-подложка → <canvas> KEmulator → body.png (прозрачное окно) → glass.png → SVG-hitboxes
```

* `views.full` — весь телефон, `views.screen` — увеличенная верхняя часть. Окно экрана — `screenRect` вида (доли размеров картинки).
* Canvas всегда вписывается в окно по правилу *contain*: отношение сторон кадра не меняется, лишнее — поля (letterbox); растягивания нет.
  «Целое масштабирование» (по умолчанию) округляет масштаб вниз до целого, если картинка при этом уменьшается не более чем на четверть.
  Это чисто презентация — разрешение эмуляции задаётся только в «Emulation profile».
* **Zoom не меняет эмуляцию.** Переключение Phone ⇄ Screen не перезапускает MIDlet, не меняет разрешение и размер canvas-буфера.
  Физических hitboxes в виде Screen нет — управление вынесено наружу: софт-клавиши и 12-клавишная панель под сценой, клавиатура ПК, gamepad.
* **Hitboxes** разбираются из `hitboxes.svg` (нормированные полигоны), попадание считается геометрически (point-in-polygon) на обёртке:
  * каждое касание/кнопка мыши — отдельный источник ввода (`skin:<модель>:<клавиша>:<pointerId>`): **мультитач**, удержание нескольких клавиш;
  * удержание: down при нажатии, up при отпускании; скольжение пальца на соседнюю клавишу отпускает первую и нажимает вторую;
  * **отпускание при `pointercancel`, потере pointer capture, `blur` окна, скрытии вкладки, смене модели, вида и размонтировании**;
  * все источники идут в общий `InputController`, тот же, что у клавиатуры, gamepad и внешней панели, поэтому состояние единое;
  * клавиша без привязки (`keyMappings: null`, например Call/End/Fn) рисуется и нажимается, но **никакого J2ME-кода не отправляет**.
* Модель — это только картинка. Она не меняет эмулируемое устройство, разрешение и коды клавиш (это делает «Emulation profile»).
  Если разрешение игры не совпало с окном модели, в панели Display появляется пометка и кнопка «Use W×H».
* Выбор модели и вида запоминается в `localStorage` (`j2me-web.skin.v1`), по умолчанию — Nokia N95-1.

## /phones

Все пять моделей × два вида, тестовая картинка вместо игры (линейка выравнивания с цветными угловыми маркерами; это не изображение игры или меню),
подсветка окна дисплея, контуры hitboxes и id клавиш, фон Light / Dark / Checker, выбор раскладки, **журнал нажатий** (down/up, код J2ME, привязка),
таблица привязок по раскладкам, статус и оговорки из `references.md`, число проверенных/использованных референсов из `reference-manifest.json`.

## Статус скинов — важно

Скины — **review draft**: оригинальные сгенерированные иллюстрации по фотографиям-референсам, не материалы производителей, не точные копии.
Техническая проверка (`python3 tools/phones/validate_assets.py`: прозрачное окно, пропорции, непересекающиеся полигоны, привязки) **не подтверждает
историческую точность**. Независимость референсов и права на их распространение остаются открытыми (см. `public/phones/references.md`,
`reference-manifest.json`); фотографии референсов в репозиторий не входят. Интерфейс помечает каждую модель как «review draft».

Что отдельно решено в конфигурациях и не придумывалось:

* 6100: четыре навигационных сектора, центральной Fire нет;
* K750i: «Back» и «C» оба дают `clear`;
* E71: вертикальный корпус с горизонтальным окном 320×240; W/A/S/D и R/T/Y/F/G/H/V/B/N/M привязаны явно как игровые решения, а не как полноценная QWERTY-клавиатура ОС;
* `glass`-слои намеренно пустые.

`body.png`/`zoom.png` не копируются в `dist` (остаются `.webp`, плагин `pruneSkinPng` в `vite.config.ts`), чтобы образ не раздувался (dist ≈ 9 МБ).

## Проверки

```bash
python3 tools/phones/validate_assets.py   # ассеты (нужны Pillow и NumPy); в CI — job phone-skins
npm test                                  # юнит: в т.ч. геометрия скинов и разбор hitboxes.svg
npm run test:e2e                          # Chromium: библиотека/плеер (browser.mjs) и скины/hitboxes/zoom (skins.mjs)
```

`tests/e2e/skins.mjs` на настоящем KEmulator проверяет: пять моделей в двух видах, положение окна по `screenRect`, отсутствие растяжения,
удержание, скольжение, клавиши без привязки, мультитач (CDP touch), `touchCancel`, `blur`, E71 W→Up, отпускание при смене вида/модели,
что zoom не перезапускает MIDlet и не меняет разрешение, letterbox 240×320 в окне K750i, сохранение выбора после перезагрузки, мобильную вёрстку.

## Что не проверено

* Только Chromium (Playwright); Safari/Firefox, реальные тач-устройства и тактильный отклик не проверялись.
* Историческая и эргономическая точность скинов не подтверждена (см. выше).
* Игры из коммерческих каталогов по-прежнему не тестировались.
