# Установка заводского комплекта VPL + FPSX

MGO принимает оригинальный `.vpl` и образы `.fpsx` напрямую. Предварительно запускать десктопный EKA2L1 и делать ROM/RPKG-дамп не нужно: MGO вызывает тот же `eka2l1::install_firmware`, который использует десктопный установщик. Прошивки предоставляет пользователь; в Git, образе и каталоге скинов их нет.

## Служба с поддержкой VPL

Закреплённый upstream `e04eb03` не предоставляет этот путь через `/v1/devices`. Поэтому сборка `mgo-symbian` применяет открытые патчи из `symbian/patches/`, добавляя поле `vpl`, индекс `variant`, прогресс и ошибки. Версия в интерфейсе получает суффикс `+jgo-vpl1`. При попытке использовать старую службу задание завершится `vpl_not_supported` с инструкцией пересобрать образ; файл не выдаётся за ROM или архив.

Пересоберите `mgo-symbian` из этой ветки с build override, как в [SYMBIAN_TESTING.md](SYMBIAN_TESTING.md). Обновить только веб-интерфейс недостаточно.

> **Интерфейс упрощён.** В *Settings → Symbian* осталась одна форма — «Firmware archive». Режим «Factory kit (.vpl + .fpsx)» из интерфейса убран; описанный ниже путь остаётся в API (`/api/symbian/firmware?slot=vpl|fpsx`), но для обычного пользователя надёжнее упаковать комплект в один архив. Установка такого архива на настоящих файлах не проверялась.

## Через браузер (устарело, только API)

1. Откройте **Settings → Symbian → Add firmware → Factory kit (.vpl + .fpsx)**.
2. В одном выборе укажите **один** `.vpl` и его `.fpsx`-образы. Сохраните исходные имена: ссылки в VPL должны совпадать с ними, включая регистр. Комплект должен быть плоской папкой, без символических ссылок и путей вида `../`.
3. Для нескольких вариантов выберите язык/регион/product code из списка. MGO не выбирает первый вариант молча. Если вариант один, он выбирается автоматически.
4. UI покажет отсутствующие FPSX для выбранного варианта и не начнёт отправку неполного комплекта. Установка на сервере повторно проверяет манифест/образы настоящим парсером EKA2L1.
5. Нажмите **Upload and install**. Видны текущий файл и прогресс. **Cancel upload** отменяет только отправку до начала установки; частичный комплект удаляется по возможности, установка не начинается.
6. После отправки запускается firmware job. Страница может быть перезагружена — мониторинг продолжится по ID задания. Дождитесь устройства в Installed devices и проверьте его модель/product code в плеере.

Лимит `MAX_FIRMWARE_MB` применяется к каждому файлу; VPL ограничен 4 МБ, комплект — 128 файлами. Варианты читаются из UTF-8 или UTF-16 с BOM; исходные байты файла не переписываются. Образы, не нужные выбранному варианту, можно не отправлять. Если выбранный VPL ссылается на форматы, отличные от `.fpsx`, интерфейс явно откажет: этот путь рассчитан на VPL/FPSX, а не на произвольные старые flash-контейнеры.

## Из inbox без HTTP-передачи больших файлов

Положите `.vpl` и все используемые `.fpsx` в одну папку `symbian-inbox/`, смонтированную в службу read-only. Выберите Factory kit, затем VPL в **Firmware from a folder**. Для многовариантного VPL укажите индекс варианта с нуля; для единственного поле можно оставить пустым. Здесь нет автоматического чтения содержимого inbox в браузер: состав и вариант окончательно проверяет ядро. Файлы inbox не переименовываются и не удаляются.

## Как сохраняются имена

Каждая браузерная отправка получает случайный bundle ID. Служба записывает файлы в отдельную папку `firmware-upload/factory/<bundle>/` под **оригинальными именами**, а не с обычными префиксами `rom-...`. Два комплекта с одинаковыми именами не смешиваются. Одновременная запись/перезапись и установка того же bundle запрещены. После задания папка комплекта удаляется целиком; установленные данные остаются в хранилище EKA2L1. Прошивки потоково проходят через MGO, без копии в его библиотеке.

API: отдельный upload на `/api/symbian/firmware?slot=vpl|fpsx&bundle=<32 hex>`, затем `POST /api/symbian/firmware/install` с `{ "vpl": "original.vpl", "bundle": "...", "variant": 0 }`. Для inbox — `{ "vpl": "original.vpl", "source": "inbox", "variant": 0 }`. Отмена незапущенного bundle — `DELETE /api/symbian/firmware/bundles/:bundle`. Нельзя смешивать `vpl` с `rom`, `rpkg` или `archive`.

## Ошибки и границы проверки

| Ошибка | Действие |
|---|---|
| `vpl_not_supported` | Пересобрать службу с патчем, затем повторить отправку комплекта. |
| `variant_required` / индекс вне списка | Явно выбрать существующий вариант; в inbox индекс начинается с нуля. |
| `vpl_invalid` | Проверить исходный VPL, его XML и FileList, не переименовывать архив в `.vpl`. |
| `firmware_file_missing` | Добавить все образы выбранного варианта под точными исходными именами; убрать пути/ссылки. |
| `fpsx_corrupt` | Проверить целостность образа и поддержку формата в EKA2L1. |
| `413` / разрыв загрузки | Проверить лимиты MGO/прокси или использовать inbox. |

При ошибке скачайте Symbian diagnostics: там есть вывод настоящего установщика. UI/API/агент и успешный транспорт комплекта проверяются с **fake** EKA2L1; тест `vpl-real-smoke.mjs` проверяет настоящий парсер/диспетчер на синтетических ошибочных данных, без прошивки. Успешная распаковка настоящего заводского комплекта и запуск игры требуют собственного комплекта и ручной проверки — автоматические тесты этого не доказывают. Ограничения десктопного VPL/FPSX-установщика EKA2L1 сохраняются; новый HTTP-путь не добавляет поддержку ранее неподдерживаемых устройств.
