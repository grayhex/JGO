# JGO в Docker (основной способ: NAS, сервер, мини-ПК)

Образ собирается в CI и лежит в GitHub Container Registry. Ничего собирать на NAS не нужно: `docker compose up -d` скачивает готовые образы.
Подходит для Synology (DSM 7.2+, Container Manager), UGREEN (UGOS), QNAP (Container Station), TrueNAS, Unraid, Portainer и обычного Linux-сервера.
Контейнер в Proxmox VE — [дополнительный способ](PROXMOX.md).

> **Статус: beta.** Конфигурация проверяется в CI на Linux (образ собирается, запускается, игры идут, права и изоляция на месте), но на настоящих NAS
> Synology/UGREEN она не проверялась: пункты меню в их приложениях зависят от версии. Универсальный способ — `docker compose` по SSH — работает везде.

## Что понадобится

| | Требование |
|---|---|
| Процессор | x86-64 (Intel/AMD). Образов для ARM пока нет |
| Память | 2 ГБ свободно (контейнер игры ограничен 1,5 ГБ; одна игра ≈ 0,25–0,5 ГБ) |
| Docker | Docker 24+ с Compose v2 (в Synology — DSM 7.2+ с Container Manager) |
| Сеть | порт 8080 (меняется) доступен из вашей сети; образам нужен выход на `ghcr.io` только при установке и обновлении |

## Быстрый старт: один YAML без .env

1. Откройте [compose.yaml](../compose.yaml) и скопируйте его содержимое в **Portainer Stack**, **Synology Container Manager → Project** или аналогичное приложение Docker на NAS.
2. В разделе `volumes` у сервиса `app` замените `${JGO_LIBRARY:-./games}` на абсолютный путь к каталогу игр на NAS, например `/volume1/games/j2me` (целиком: `/volume1/games/j2me:/mnt/jgo-library:ro`). Для хранения данных в обычной папке замените левую часть `${JGO_DATA:-jgo-data}` на `/volume1/docker/jgo/data` и укажите UID:GID владельца (или пользователя с разрешённой записью) в `user`. **Bind mount не меняет владельца папки автоматически:** заранее предоставьте этому UID право на чтение и запись на NAS.
3. Нажмите **Deploy**. Образы `ghcr.io/grayhex/jgo` и `jgo-gateway` загрузятся автоматически, без исходников.
4. В логах контейнера **app** найдите строку `[JGO] First-run login token:`, скопируйте токен. Это секрет, не публикуйте логи.
5. Откройте `http://<адрес NAS>:8080`, войдите по токену и пройдите мастер первоначальной настройки (внутренний путь к играм: `/mnt/jgo-library`).



**UGREEN и права файла токена.** На некоторых сетевых файловых системах/ACL файл в bind mount `/data/.jgo-auth-token` может выглядеть как `0644` или `0777` даже при корректном UID:GID. JGO намеренно не ослабляет проверку `0600`: новый Compose хранит токен **в отдельном Docker named volume `jgo-auth:/jgo-auth`**, а папка `/volume1/Docker/jgo` остаётся для данных. Ранее созданный `/data/.jgo-auth-token` не используется новым режимом, новый токен появится в логах при первом старте. Не удаляйте старые данные или секреты вслепую, сначала убедитесь, что новая авторизация работает.

### Ошибка `EACCES` при создании токена

Если `app` пишет `Cannot provision login token: EACCES` или `Data directory /data is not writable`, ошибка **в правах папки на NAS**, а не в токене. Приложение по умолчанию работает с `user: "10001:10001"`, а каталог `/volume1/Docker/jgo` может принадлежать пользователю NAS `1000:10`.

Для собственного каталога в `services → app` укажите, например, `user: "1000:10"` и подключите `/volume1/Docker/jgo:/data`; на NAS разрешите **запись** этому UID. Конкретные UID/GID зависят от NAS, не копируйте значения вслепую. Если папка уже содержит файлы от старого UID, проверьте доступ к ним **до** смены пользователя и сделайте резервную копию.

Если нужен максимально простой вариант без NAS ACL, используйте **`jgo-data:/data`** вместе со стандартным `user: "10001:10001"`. Если хотите оставить пользовательский путь `/volume1/Docker/jgo:/data`, можно использовать UID/GID NAS, поскольку токен теперь отделён в Docker volume `jgo-auth`. Это Docker-managed volume, а не папка File Station. Существующий каталог данных не удаляйте и не переносите без бэкапа. **Не используйте `chmod 777` и не удаляйте том при обновлении.**

JGO генерирует криптографически случайный токен **один раз** и хранит его в отдельном Docker-томе `jgo-auth` по пути `/jgo-auth/.jgo-auth-token` (права 0600). Это защищает токен от конфликтов с ACL общих папок NAS. Он переживает обновления и рестарты вместе с остальными пользовательскими данными. Не удаляйте том `jgo-auth` при обновлении: иначе токен будет сгенерирован заново. Если первый лог недоступен, прочитайте токен из `/jgo-auth/.jgo-auth-token` через консоль контейнера или `docker compose exec app cat /data/.jgo-auth-token`. Без токена доступ не открывается, даже в локальной сети.

Для Linux с терминалом достаточно:

```bash
mkdir jgo && cd jgo
curl -fsSLO https://raw.githubusercontent.com/grayhex/JGO/main/compose.yaml
docker compose up -d
docker compose logs app
```

Необязательный `.env` по-прежнему поддерживается для автоматизации и старых установок (`JGO_TOKEN`, `JGO_DATA`, `PUID`/`PGID`, `JGO_VERSION`), но **не требуется**. Конфигурация также прикрепляется к [релизам](https://github.com/grayhex/JGO/releases); GitHub `/releases/latest` не показывает prerelease.

## Synology (DSM 7.2+)

1. Установите **Container Manager** через Package Center.
2. Откройте **Container Manager → Project → Create**. Создайте проект `jgo` и вставьте содержимое [compose.yaml](../compose.yaml) (либо сохраните этот единственный файл в каталоге проекта).
3. В YAML замените путь `./games` на `/volume1/games/j2me` или ваш реальный путь. Для данных можно оставить именованный том `jgo-data`, либо указать `/volume1/docker/jgo/data:/data` и `user: "1026:100"` с подходящими правами.
4. Разверните проект, откройте логи контейнера `app`, скопируйте токен первой установки и войдите по `http://<адрес NAS>:8080`. Порт меняется непосредственно в `ports` сервиса `gateway` (например, `8090:8080`).

## UGREEN (UGOS)

1. Установите приложение **Docker** и создайте проект `jgo` из одного `compose.yaml` (вставкой YAML или сохранением файла).
2. В YAML замените `./games` на путь вашей папки с играми на NAS. Если используете отдельную папку данных, задайте её владельца через `user` или необязательные `PUID`/`PGID`.
3. Нажмите Deploy, откройте логи контейнера `app` и скопируйте автоматически созданный токен.

## Portainer, QNAP, TrueNAS, Unraid

Создайте *Stack* из содержимого `compose.yaml`. Ничего не добавляйте в Environment: токен создаётся автоматически. При необходимости поправьте пути, порт и UID/GID прямо в YAML.

## Настройки

Для обычного пользователя всё можно менять в самом `compose.yaml` (после правки: redeploy / `docker compose up -d`). Те же поля при желании можно задавать через необязательный `.env`:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `JGO_TOKEN` | автоматически создан в `/jgo-auth/.jgo-auth-token` | необязательный вручную заданный токен входа, ≥ 16 символов |
| `JGO_VERSION` | `latest` | версия образа; для предсказуемых обновлений укажите конкретную, например `0.1.0-beta.1` |
| `JGO_PORT` | `8080` | порт на хосте |
| `JGO_BIND` | `0.0.0.0` | на каком адресе слушать; `127.0.0.1` — только сам хост (когда впереди обратный прокси) |
| `JGO_DATA` | том `jgo-data` | имя тома или абсолютный путь к папке данных |
| `PUID`, `PGID` | `10001`, `10001` | от чьего имени работает приложение (нужны, когда `JGO_DATA` — папка) |
| `JGO_LIBRARY` | `./games` | папка с коллекцией `.jar`/`.jad` (только чтение) |
| `MAX_SESSIONS` | `1` | число одновременных игр |
| `MEM_LIMIT`, `CPUS` | `1536m`, `2` | лимиты контейнера |
| `SESSION_MAX_MINUTES`, `SESSION_IDLE_MINUTES` | `120`, `5` | предел длительности и таймаут простоя |
| `LIBRARY_QUOTA_MB` | `4096` | квота библиотеки |
| `ALLOWED_ORIGINS` | — | внешний адрес, если интерфейс открывают через обратный прокси |
| `MOBYGAMES_API_KEY` | — | ключ MobyGames (можно ввести в Settings) |

Остальные параметры приложения (`FRAME_ENCODING`, `KEM_CPU_SECONDS`, …) перечислены в [`packaging/jgo.env.example`](../packaging/jgo.env.example); в `compose.yaml` пробрасывается только часть. Нужен другой — добавьте строку в раздел `environment` сервиса `app`.

## Данные и резервные копии

Библиотека, настройки, сохранения игр (RMS), SoundFont, файлы игр и журналы лежат в `/data` контейнера: в томе `jgo-data` или в папке `JGO_DATA`. **Токен входа хранится отдельно, в именованном томе `jgo-auth`.** Не удаляйте эти два тома при обновлении; резервное копирование должно учитывать оба.

Резервная копия (на время копирования лучше остановить приложение — база SQLite):

```bash
docker compose stop app
# папка JGO_DATA:
tar czf jgo-backup-$(date +%F).tgz -C /volume1/docker/jgo data
# или том Docker:
docker run --rm -v jgo_jgo-data:/data -v "$PWD":/backup alpine tar czf /backup/jgo-backup-$(date +%F).tgz -C /data .
docker compose start app
```

Папку `JGO_DATA` можно включить в Hyper Backup / Snapshot Replication / любое резервное копирование NAS. Восстановление: остановить, распаковать архив в то же место, запустить.
Для резервной копии токена дополнительно сохраните отдельный том `jgo_jgo-auth` (или его фактическое имя в Docker), например через NAS Docker Volume Backup. Не храните бэкап токена в публичном доступе.
Команды `jgo` (update, backup, doctor) в Docker нет — она есть только в контейнере Proxmox.

## Обновление

```bash
docker compose pull
docker compose up -d
```

В Synology Container Manager: *Проект → jgo → Действие → Сборка* (скачивает новые образы и пересоздаёт контейнеры). С `JGO_VERSION=latest` обновление берёт самый новый выпуск; перед обновлением сделайте резервную копию. Откат — вернуть прежний номер в `JGO_VERSION` и выполнить `docker compose up -d`.

## Доступ извне и HTTPS

JGO по умолчанию открыт только в вашей сети по HTTP. Не пробрасывайте порт 8080 из интернета напрямую. Если нужен доступ снаружи — VPN (WireGuard/Tailscale) либо обратный прокси с TLS:

1. В `compose.yaml`: замените порт шлюза на `127.0.0.1:8080:8080` и пропишите `ALLOWED_ORIGINS: https://jgo.example.com` для сервиса `app` (или используйте необязательный `.env`).
2. Прокси (Synology: *Панель управления → Портал входа → Обратный прокси*; Caddy; nginx) направляет `https://jgo.example.com` на `http://127.0.0.1:8080` и **пропускает WebSocket** (заголовки `Upgrade`/`Connection`; в Synology — вкладка «Пользовательские заголовки → WebSocket»). Таймаут чтения — не меньше часа.

Копирование снимка экрана в буфер обмена браузер разрешает только на страницах по HTTPS (или с `localhost`); сохранение файлом работает всегда.

## Сеть игр

В `compose.yaml` приложение подключено только к внутренней сети Docker без маршрута наружу: игра не может обратиться ни в интернет, ни к вашему NAS и принтерам. Это защита, а не неполадка. Игре из старого каталога нужен интернет (счёт, реклама)? Осознанно:

```bash
docker compose -f compose.yaml -f compose.egress.yaml up -d
```

Игра сможет обращаться ко всему, что доступно контейнеру, включая вашу локальную сеть. Включайте только для игр, которым доверяете.

## Безопасность

* Контейнер приложения работает не от root, с файловой системой «только чтение», без привилегий (`cap_drop: ALL`, `no-new-privileges`), с лимитами памяти, процессов и CPU.
* Порт публикует только шлюз (nginx) — приложение изолировано во внутренней сети.
* Токен проверяется для всего API; сравнивается безопасно по времени. Автоматически созданный токен хранится в `/jgo-auth/.jgo-auth-token`, а при первом запуске появляется в логах Docker. Не публикуйте этот лог и токен.
* Подробности и известные пробелы — [SECURITY.md](SECURITY.md).

## Если что-то не так

| Симптом | Причина и решение |
|---|---|
| `Cannot provision login token` | проверьте права записи контейнера в `/data` и наличие места на диске; не удаляйте существующий токен ради обхода ошибки |
| `AUTH_TOKEN must be at least 16 characters` в журнале | токен короче 16 символов |
| В журнале `EACCES`, `permission denied` или `Data directory /data is not writable` | В `services.app.user` задайте UID:GID с правом записи в каталог NAS или вернитесь к Docker volume `jgo-data:/data` и `10001:10001`; подробнее см. выше |
| `port is already allocated` | порт 8080 занят: `JGO_PORT=8090` |
| Страница открывается, но игра не стартует, в журнале нет места | мало памяти: проверьте `MEM_LIMIT`, закройте лишние контейнеры |
| `denied` / `unauthorized` при загрузке образа | пакеты на `ghcr.io` должны быть публичными — владелец репозитория включает это один раз (*Packages → Package settings → Change visibility*) |
| Интерфейс за обратным прокси: «белый экран» / нет картинки | не пропускается WebSocket или не задан `ALLOWED_ORIGINS` |
| За пределами локальной сети нет звука | звук включается после первого нажатия на странице (требование браузера) |

Журналы: `docker compose logs -f app`. Отчёт для сообщения об ошибке: в плеере — *Session → Download diagnostics* (в образе есть `jcmd`, поэтому в отчёт попадают куча и потоки JVM).

## Сборка из исходников

```bash
git clone https://github.com/grayhex/JGO && cd JGO
docker compose -f compose.yaml -f compose.build.yaml up -d --build
```

Только `compose.build.yaml` включает сборку из исходников; обычный `compose.yaml` использует готовые GHCR-образы. Первая сборка занимает 10–20 минут (клонируется и собирается KEmulator, компилируется Rust-адаптер). Образ использует закреплённый коммит KEmulator и патчи из `runtime/patches`; других внешних исходников в репозитории нет.
