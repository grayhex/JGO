# JGO в Docker (основной способ: NAS, сервер, мини-ПК)

Образ собирается в CI и лежит в GitHub Container Registry. Ничего собирать на NAS не нужно: `docker compose up -d` скачивает готовые образы.
Подходит для Synology (DSM 7.2+, Container Manager), UGREEN (UGOS), QNAP (Container Station), TrueNAS, Unraid, Portainer и обычного Linux-сервера.
Контейнер в Proxmox VE — [дополнительный способ](PROXMOX.md).

> **Статус: beta.** Конфигурация проверяется в CI на Linux (образ собирается, запускается, игры идут, права и изоляция на месте), но на настоящих NAS
> Synology/UGREEN она не проверялась: пункты меню в их приложениях зависят от версии. Универсальный способ — `docker compose` по SSH — работает везде.

## Что понадобится

| | Требование |
|---|---|
| Процессор | x86-64 (Intel/AMD). Образов для ARM пока нет |
| Память | 2 ГБ свободно (контейнер игры ограничен 1,5 ГБ; одна игра ≈ 0,25–0,5 ГБ) |
| Docker | Docker 24+ с Compose v2 (в Synology — DSM 7.2+ с Container Manager) |
| Сеть | порт 8080 (меняется) доступен из вашей сети; образам нужен выход на `ghcr.io` только при установке и обновлении |

## Быстрый старт

Любой компьютер с Docker (по SSH или в терминале):

```bash
mkdir jgo && cd jgo
curl -fsSLO https://github.com/grayhex/JGO/releases/latest/download/compose.yaml
curl -fsSL https://github.com/grayhex/JGO/releases/latest/download/env.example -o .env
```

Откройте `.env` и впишите токен доступа (не короче 16 символов). Сгенерировать:

```bash
openssl rand -hex 16
```

```bash
docker compose up -d
```

Откройте `http://<адрес NAS>:8080`, введите токен и пройдите мастер первого запуска (папка с играми, MobyGames — по желанию).

Без токена Compose не запустится: веб-интерфейс виден всей сети, а игры — чужой код.

## Synology (DSM 7.2+)

1. **Package Center** → установите **Container Manager**.
2. **File Station**: в общей папке `docker` создайте папку `jgo`. Положите в неё `compose.yaml` и `.env` (его удобно подготовить на компьютере: скачать `env.example` из релиза, переименовать в `.env`, вписать `JGO_TOKEN`; файл с точкой в начале может быть скрыт — включите показ скрытых файлов).
3. Узнайте номера пользователя и группы: по SSH выполните `id <ваше имя>` (у администратора обычно `uid=1026`, `gid=100`).
4. Хотите хранить данные в обычной папке, которую видно в File Station и которую копирует Hyper Backup? Создайте `docker/jgo/data` и допишите в `.env`:

   ```
   JGO_DATA=/volume1/docker/jgo/data
   PUID=1026
   PGID=100
   ```

   У пользователя `PUID` должны быть права на чтение и запись этой папки (File Station → Свойства → Разрешения). Без этих трёх строк данные лежат в томе Docker: прав настраивать не нужно, но папку в File Station не видно.
5. **Container Manager → Проект → Создать**: имя `jgo`, путь `/volume1/docker/jgo`, источник — существующий `compose.yaml`. Нажмите «Далее» до конца, проект запустится сам.
6. Откройте `http://<адрес NAS>:8080`. Порт 8080 занят чем-то другим? Допишите в `.env` `JGO_PORT=8090` и пересоздайте проект.

Игры лежат на NAS? Допишите в `.env` `JGO_LIBRARY=/volume1/games/j2me` (папка монтируется внутрь **только для чтения**), перезапустите проект и выберите `/mnt/jgo-library` в *Settings → Game library*.

## UGREEN (UGOS)

1. Приложение **Docker** (в некоторых версиях UGOS его нужно установить из «Центра приложений»).
2. Создайте на накопителе папку, например `docker/jgo`, положите в неё `compose.yaml` и `.env` (как выше).
3. **Docker → Проект → Создать**, укажите эту папку и существующий `compose.yaml`.
4. Для папки данных на накопителе выясните `PUID` и `PGID` командой `id <имя>` по SSH (включается в настройках NAS) и впишите их в `.env` вместе с `JGO_DATA=<путь к папке>`.
5. Если в вашей версии UGOS нет проектов Compose или они не читают `.env`: по SSH зайдите в папку и выполните `docker compose up -d`. Контейнеры появятся в приложении Docker.

## Portainer, QNAP, TrueNAS, Unraid

Создайте *Stack* из содержимого `compose.yaml` и добавьте переменные из `env.example` в поле окружения стека (`JGO_TOKEN` обязателен). В остальном всё то же самое.

## Настройки

Всё меняется в `.env` (после правки: `docker compose up -d`, контейнеры пересоздадутся).

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `JGO_TOKEN` | — (обязательна) | токен входа, ≥ 16 символов |
| `JGO_VERSION` | `latest` | версия образа; для предсказуемых обновлений укажите конкретную, например `0.1.0-beta.1` |
| `JGO_PORT` | `8080` | порт на хосте |
| `JGO_BIND` | `0.0.0.0` | на каком адресе слушать; `127.0.0.1` — только сам хост (когда впереди обратный прокси) |
| `JGO_DATA` | том `jgo-data` | имя тома или абсолютный путь к папке данных |
| `PUID`, `PGID` | `10001`, `10001` | от чьего имени работает приложение (нужны, когда `JGO_DATA` — папка) |
| `JGO_LIBRARY` | `./games` | папка с коллекцией `.jar`/`.jad` (только чтение) |
| `MAX_SESSIONS` | `1` | число одновременных игр |
| `MEM_LIMIT`, `CPUS` | `1536m`, `2` | лимиты контейнера |
| `SESSION_MAX_MINUTES`, `SESSION_IDLE_MINUTES` | `120`, `5` | предел длительности и таймаут простоя |
| `LIBRARY_QUOTA_MB` | `4096` | квота библиотеки |
| `ALLOWED_ORIGINS` | — | внешний адрес, если интерфейс открывают через обратный прокси |
| `MOBYGAMES_API_KEY` | — | ключ MobyGames (можно ввести в Settings) |

Остальные параметры приложения (`FRAME_ENCODING`, `KEM_CPU_SECONDS`, …) перечислены в [`packaging/jgo.env.example`](../packaging/jgo.env.example); в `compose.yaml` пробрасывается только часть. Нужен другой — добавьте строку в раздел `environment` сервиса `app`.

## Данные и резервные копии

Всё, что хранит JGO — библиотека, настройки, сохранения игр (RMS), SoundFont, файлы игр, журналы, — лежит в `/data` контейнера: в томе `jgo-data` или в папке `JGO_DATA`.

Резервная копия (на время копирования лучше остановить приложение — база SQLite):

```bash
docker compose stop app
# папка JGO_DATA:
tar czf jgo-backup-$(date +%F).tgz -C /volume1/docker/jgo data
# или том Docker:
docker run --rm -v jgo_jgo-data:/data -v "$PWD":/backup alpine tar czf /backup/jgo-backup-$(date +%F).tgz -C /data .
docker compose start app
```

Папку `JGO_DATA` можно включить в Hyper Backup / Snapshot Replication / любое резервное копирование NAS. Восстановление: остановить, распаковать архив в то же место, запустить.
Команды `jgo` (update, backup, doctor) в Docker нет — она есть только в контейнере Proxmox.

## Обновление

```bash
docker compose pull
docker compose up -d
```

В Synology Container Manager: *Проект → jgo → Действие → Сборка* (скачивает новые образы и пересоздаёт контейнеры). С `JGO_VERSION=latest` обновление берёт самый новый выпуск; перед обновлением сделайте резервную копию. Откат — вернуть прежний номер в `JGO_VERSION` и выполнить `docker compose up -d`.

## Доступ извне и HTTPS

JGO по умолчанию открыт только в вашей сети по HTTP. Не пробрасывайте порт 8080 из интернета напрямую. Если нужен доступ снаружи — VPN (WireGuard/Tailscale) либо обратный прокси с TLS:

1. В `.env`: `JGO_BIND=127.0.0.1` и `ALLOWED_ORIGINS=https://jgo.example.com`.
2. Прокси (Synology: *Панель управления → Портал входа → Обратный прокси*; Caddy; nginx) направляет `https://jgo.example.com` на `http://127.0.0.1:8080` и **пропускает WebSocket** (заголовки `Upgrade`/`Connection`; в Synology — вкладка «Пользовательские заголовки → WebSocket»). Таймаут чтения — не меньше часа.

Копирование снимка экрана в буфер обмена браузер разрешает только на страницах по HTTPS (или с `localhost`); сохранение файлом работает всегда.

## Сеть игр

В `compose.yaml` приложение подключено только к внутренней сети Docker без маршрута наружу: игра не может обратиться ни в интернет, ни к вашему NAS и принтерам. Это защита, а не неполадка. Игре из старого каталога нужен интернет (счёт, реклама)? Осознанно:

```bash
docker compose -f compose.yaml -f compose.egress.yaml up -d
```

Игра сможет обращаться ко всему, что доступно контейнеру, включая вашу локальную сеть. Включайте только для игр, которым доверяете.

## Безопасность

* Контейнер приложения работает не от root, с файловой системой «только чтение», без привилегий (`cap_drop: ALL`, `no-new-privileges`), с лимитами памяти, процессов и CPU.
* Порт публикует только шлюз (nginx) — приложение изолировано во внутренней сети.
* Токен проверяется для всего API; сравнивается безопасно по времени. Не публикуйте токен и `.env`.
* Подробности и известные пробелы — [SECURITY.md](SECURITY.md).

## Если что-то не так

| Симптом | Причина и решение |
|---|---|
| `required variable JGO_TOKEN is missing` | не создан `.env` рядом с `compose.yaml` или в нём пустой `JGO_TOKEN` |
| `AUTH_TOKEN must be at least 16 characters` в журнале | токен короче 16 символов |
| В журнале `EACCES` / `permission denied` на `/data` | `JGO_DATA` — папка, которой владеет другой пользователь: задайте `PUID`/`PGID` её владельца или дайте ему права записи |
| `port is already allocated` | порт 8080 занят: `JGO_PORT=8090` |
| Страница открывается, но игра не стартует, в журнале нет места | мало памяти: проверьте `MEM_LIMIT`, закройте лишние контейнеры |
| `denied` / `unauthorized` при загрузке образа | пакеты на `ghcr.io` должны быть публичными — владелец репозитория включает это один раз (*Packages → Package settings → Change visibility*) |
| Интерфейс за обратным прокси: «белый экран» / нет картинки | не пропускается WebSocket или не задан `ALLOWED_ORIGINS` |
| За пределами локальной сети нет звука | звук включается после первого нажатия на странице (требование браузера) |

Журналы: `docker compose logs -f app`. Отчёт для сообщения об ошибке: в плеере — *Session → Download diagnostics* (в образе есть `jcmd`, поэтому в отчёт попадают куча и потоки JVM).

## Сборка из исходников

```bash
git clone https://github.com/grayhex/JGO && cd JGO
cp .env.example .env    # впишите JGO_TOKEN
docker compose up -d --build
```

Первая сборка занимает 10–20 минут (клонируется и собирается KEmulator, компилируется Rust-адаптер). Образ использует закреплённый коммит KEmulator и патчи из `runtime/patches`; других внешних исходников в репозитории нет.
