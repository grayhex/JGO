Честные оговорки:

* **Коммерческих игр у меня не было, и я их не проверял.** Реальная сторонняя игра ровно одна — GAEM (GPL, не добавлена в Git; JAR берётся из
  каталога корпуса). Остальное — собственные CC0-фикстуры `tests/fixtures/labgames`, которые покрывают API, но не заменяют настоящий
  Gameloft/Mascot Capsule/Nokia-контент. Прогон на вашем корпусе: `npm run lab -- run /путь/к/играм`.
* `WARN` у `kemnet`, `kemscreens-canvascmd`, `kemscreens-textbox` — статичные экраны по замыслу фикстур; у `TextBox` это реальное ограничение
  (ввод текста не реализован эмулятором в Bridge).
* FPS=0 у GAEM, Alert и List — игра/экран перерисовывается только по событию; лаборатория не считает это ошибкой.
* Звук в корпусе не проверялся (`—` значит «игра не играла звук за время замера»); серверный звуковой тракт проверен отдельными тестами.
* RSS/CPU — процессное дерево Java + supervisor, по `/proc`; CPU усреднён за весь запуск, включая загрузку JVM.

## Что проверено, а что нет

* **2D** — `Canvas`/`Graphics`, шрифты (AWT, DejaVu), `Image`, RMS, `Thread`-анимация: ✔.
* **M3G (JSR-184)** — immediate-mode рендер в `Canvas` через LWJGL/OpenGL на программном Mesa: ✔ (одна сцена). Retained mode, текстуры,
  освещение, `World`/`.m3g`-загрузка — не проверялись.
* **Mascot Capsule** — не проверялось.
* **Звук** — серверная часть ✔ (WAV Clip, MIDI/Gervill → PCM по WebSocket; частота и уровень проверены автотестом);
  браузер ✔ до выхода AudioWorklet (уровень сигнала > 0 в headless Chromium). Слышимость в реальных динамиках я не проверял.
  MP3 (javazoom), AMR, VLC-пути — не проверялись; vlcj в контейнере недоступен.
* **RMS** — переживает перезапуск сессии, сервера и контейнера; изолирован по играм (`saves/<owner>/<gameId>`).
* **Ввод** — клавиши, мульти-нажатие, key-repeat (`R`), pointer-события отправляются; проверка на реальных играх впереди.
* **Раскладки** (`packages/protocol`): Nokia/Sony Ericsson (-1…-8; именно они проверены на `getGameAction` тестового MIDlet).
  Siemens (`-26` = FIRE) и Motorola V300 проверены автотестом `devices.test.ts`: API записывает `midlets.ini` с device-пресетом KEmulator.
* **Профили телефонов**: подключены 59 пресетов KEmulator (`GET /api/devices`; модель, разрешение, раскладка, `microedition.platform`). Выбор пресета в UI не добавлен — визуальные компоненты ведёт другой агент.

## Известные ограничения эмулятора/интеграции

* Class-файлы ≥ 49 не запускаются (понятная ошибка при старте и предупреждение при загрузке).
* `List`/`TextBox` рисуются программно (патч `0006`), но ввод текста в Bridge по-прежнему не реализован.
* Нет эмуляции Bluetooth/камеры/телефонии; сеть — по политике контейнера (по умолчанию выключена).
* `Fake soft bar`: у не-fullscreen `Canvas` внизу кадра остаётся пустая полоса высотой в бордюр эмулятора.
* Диагностика неподдерживаемых API — по тексту лога (ClassNotFound/NoSuchMethod/Not implemented/OOM/GL), см. панель «Diagnostics».
