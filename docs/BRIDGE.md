# KEmulator Bridge: что проверено на практике

Источник: `shinovon/KEmulator`, тег **v2.22**, commit `9ec1005af5448bca63a420e1dfa884ef53842d0f`
(`BridgeFrontendDocs.md`, `src/main/emulator/ui/bridge/*`, `Emulator.java`). Протокол помечен автором как экспериментальный.

## Как мы его используем

`kem-adapter` (Rust) создаёт в каталоге сессии `inputpipe`, `statepipe`, `readypipe`, `readpipe` и запускает JVM.
Открытие FIFO строго в порядке эмулятора: `inputpipe`(W) → `statepipe`(R) → `readypipe`(R) → `readpipe`(W);
`screen` открывается mmap'ом после рукопожатия. Цикл кадров: прочитать байт из `readypipe` → скопировать mmap
(с конвертацией в RGBA) → **сразу** записать `\n` в `readpipe` → кодировать/отправлять копию. Устаревшие кадры
отбрасываются (mailbox из одного кадра), блокировок FIFO нет: если JVM умирает до рукопожатия, супервизор это видит
(`try_wait`) и таймаут рукопожатия убивает группу процессов. Остановка — собственная команда `Q` (патч `0009`): штатный `MIDlet.destroyApp(true)`, затем закрытие `inputpipe`; если игра не ответила за 8 с, группе процессов уходит SIGKILL (см. [SESSION_RECOVERY.md](SESSION_RECOVERY.md)).

## Расхождения с документацией (найдены экспериментально)

| # | Документация | Реальность v2.22 | Что сделано |
|---|---|---|---|
| 1 | `-bridge <FOLDER>` | `Emulator.main` выбирает фронтенд **до** разбора аргументов, поэтому `-bridge` не действует: запускается SWT (падает без GTK/дисплея). Каталог зашит как `/tmp/kem/`. То же в `main` на момент проверки. Релизный `KEmulator.jar` (obfuscated) ведёт себя так же. | Патч `0001`: предварительный разбор `-bridge [FOLDER]` и `-screen WxH`. |
| 2 | Размер экрана «указывается эмулятору» | Единственный способ — `-screen WxH`; также читается *до* создания фреймбуфера (см. п.1). | Входит в патч `0001`. |
| 3 | Фреймбуфер RGBA8888 | Байты в буфере: **A, R, G, B** (big-endian `putInt(0xAARRGGBB)`). Проверено цветными блоками в тестовом MIDlet. | Адаптер переставляет в RGBA и ставит A=255. |
| 4 | — | Классы MIDlet версии ≥ 49 (Java 5+) отвергаются (`Invalid class version`). | Проверка при загрузке JAR + понятная ошибка. |
| 5 | — | `Canvas` без fullscreen рисует в кадр плашку «Fake soft bar». | Патч `0003` убирает надпись (область остаётся). Подписи софт-клавиш приходят пакетом `C`. |
| 6 | — | `Property.pickFont` требует SWT/GTK и роняет JVM `UnsatisfiedLinkError`'ом (и прерывает `loadProperties`). | Патч `0004`: шрифты берутся из AWT. |
| 7 | — | RMS, настройки и `file:///` хранятся в «user path» (портативный режим = каталог эмулятора, общий для всех игр). | Патч `0002`: `-Dkem.userpath`, у нас `data/saves/<owner>/<gameId>`. |
| 8 | Типы экранов `TextBox`/`List` | В стоковой сборке `setCurrent` бросает `IllegalArgumentException("Not implemented")`; пакет `E` (ввод текста) тоже `Not implemented`, пакет `A` не отправляется никогда. | Экраны рисуются программно — см. п. 9 и патч `0006`. **Ввод текста** на момент аудита был невозможен (проверено `tools/audit/probe.mjs`); теперь он работает через патч `0010` (см. «Расширения JGO» ниже).

### Найдено компатибилити-лабораторией (ветка `feat/compatibility-lab`)

Каждый пункт воспроизводился на стоковой сборке v2.22 и закрыт патчем + регрессионным тестом в
`tests/integration/bridge-regressions.test.ts` (и `devices.test.ts`).

| # | Симптом | Причина в эмуляторе | Исправление |
|---|---|---|---|
| 9 | Игра с `List` или `TextBox` не выдаёт ни одного кадра (`NullPointerException ... SWTFrontend.display`) | `List`/`TextBox` создают SWT-виджеты (`ListSWT`, `TextBoxSWT`); в Bridge нет SWT-дисплея, исключение летит прямо в конструктор. `BridgeOutput.setCurrent` для них ещё и бросал «Not implemented» | Патч `0006`: `ListHeadless`/`TextBoxHeadless` — программные реализации на той же модели `ChoiceImpl`; рисуются в фреймбуфер как `Form`/`Alert`, список управляется d-pad/Fire (`select command`), `D`-пакет всегда `B`. Ввод текста в `TextBox` добавлен позже патчем `0010` |
| 10 | В логе каждой игры без иконки: `IOException ... "buf" is null` | `Emulator.main` передаёт `null` в `setWindowIcon`, `ImageAWT(null)` падает | Патч `0005` |
| 11 | Стек-трейсы `net.java.games.input` в каждом запуске | пробуются геймпады в `/dev/input`, которого нет | Патч `0007`: в Bridge не вызывается `Controllers.refresh` |
| 12 | `MIDlet.platformRequest(url)` выбрасывает `ConnectionNotFoundException`; пакет `U` из спецификации не отправляется никогда. При наличии `xdg-open` эмулятор запускал **браузер на сервере** по требованию недоверенной игры | `Emulator.openUrlExternally` не знает про Bridge | Патч `0008`: в Bridge URL уходит пакетом `U`; API пропускает клиенту только `http(s)`, `mailto`, `tel` |
| 13 | Игра, запросившая разрешение (`platformRequest`, HTTP), зависает навсегда, если клиент не ответил/закрыл вкладку | `PermissionWaitData.request` делает `lock.wait()` без таймаута; блокируется поток обработки событий игры | API: нет зрителей — отказ сразу; иначе отказ через `PERMISSION_TIMEOUT_SECONDS` (60); отказ при уходе последнего зрителя |
| 14 | Выбор раскладки (Siemens, Motorola) не влиял на то, как эмулятор переводит коды клавиш в игровые действия | клиент слал коды выбранной раскладки, а эмулятор всегда держал раскладку Nokia (`-26` не был FIRE у Siemens) | API пишет `midlets.ini` игры (`DevicePreset`, `Key*`, `IgnoreFullScreenMode`, `MIDPPlatform`) перед запуском — без патча эмулятора |
| 15 | `Class files ... RuntimeException` на классах, собранных javac 21 | ASM API 4 в эмуляторе падает на атрибуте `MethodParameters` (его пишет javac ≥ 21 для анонимных классов) | Не баг эмулятора для настоящих J2ME-игр (там атрибута нет); фикстуры теперь «даунгрейдятся» (`tests/fixtures/tools/j2me_downgrade.py`). Анализатор лаборатории может сообщать о нём как о версии классов |
| 16 | Штатная остановка игры иногда считалась крахом: `emulator exited with code 27: bridge: readpipe closed unexpectedly` сразу после `[session] stopping` (1 из ~13 запусков в лаборатории) | При закрытии `inputpipe` эмулятор может раньше заметить закрытый соседний пипс и выйти с кодом 25–29 | `kem-adapter`: код 25–29 после запроса `Q` — это штатная остановка (`code 0`, «stopped on request»); без запроса остаётся сбоем. Юнит-тест `quit_race_tests` в `main.rs` |

Не исправлено (ограничения эмулятора, а не интеграции): `Alert` без таймаута ждёт клавишу, `Canvas.setFullScreenMode(false)` отдаёт полосу
высоты бордюра, Mascot Capsule проверен только на примитивах без `.mbac`.

Пакеты `statepipe` проверены автотестами с реальным эмулятором: `L`, `C`, `T`, `D`, `M` (меню команд), `V` (вибрация), `P` (разрешение), `U` (URL).
`O` обрабатывается сессией, но тестами не вызывался. `I` (иконка) эмулятор отправляет (проверено `tools/audit/probe.mjs`), сессия его не использует; `A` (область ввода текста) эмулятор не отправляет никогда. Входные события `K D/U/R`, `T` (pointer), `C` (команда меню) и `P` (ответ на разрешение) проверены автотестами.

## Расширения JGO (патчи 0010–0013)

Эти пакеты и команды нет в спецификации Bridge; они проверены `tests/integration/bridge-contract.test.ts` и профильными тестами.

| Направление | Пакет | Формат | Патч | Что делает |
|---|---|---|---|---|
| в эмулятор | `E <текст>` | текст — UTF-8 в percent-encoding (адаптер пропускает только ASCII) | 0010 | вводит текст в сфокусированный `TextField`/`TextBox`: усечение до `maxSize`, фильтр по `NUMERIC`/`DECIMAL`/`PHONENUMBER`, `itemStateChanged`; без фокуса игнорируется |
| из эмулятора | `N` | `u32 maxSize`, `u32 constraints`, `u8 'F'/'B'` | 0010 | свойства области ввода; всегда идёт **перед** `A` |
| из эмулятора | `A` | `i16 x, y, w, h` + UTF-8 текст; без данных = области нет | 0010 | как в спецификации: область ввода и её текущий текст (повторяется после каждого принятого `E`) |
| в эмулятор | `S 1` / `S 0` | — | 0012 | приостановить игру (`hideNotify`, `pauseApp`, заморозка цикла отрисовки) / продолжить (`startApp`, `showNotify`); при `StartAppOnResume=false` вызываются только `hideNotify`/`showNotify` |
| в эмулятор | `Y <n>` | целое −100…100, кроме 0 | 0013 | скорость игры (модификатор KEmulator: 1 — норма, 2…100 быстрее, −1…−100 медленнее, −50 — вдвое медленнее) |
| из эмулятора | `U` | UTF-8 адрес | 0008 | `platformRequest`; сервер пропускает только `http(s)`, `mailto`, `tel` |

Кроме того, патч `0011` делает `getMessage()` заглушкой (SMS → `IOException`), патч `0013` исправляет растяжение `Thread.sleep` при замедлении.
Команды `E` без фокуса, `I` (не реализована ядром), `X` (не меняет картинку), `X 2`, `S 2`, неизвестные типы и неполные строки безопасны:
эмулятор пишет исключение в журнал и продолжает работу.

## Звук (вне спецификации Bridge)

В контейнере нет звуковой карты, поэтому Java Sound не видит устройств. `runtime/audio` — свой `MixerProvider`
(Clip + SourceDataLine, микширование, ресемплинг, «часы» по 10 мс), встраиваемый в `KEmulator.jar`; PCM (s16le, 44.1 кГц, стерео)
пишется в FIFO `audio`, адаптер читает его и пересылает как сообщения `A`. PulseAudio/PipeWire не требуются.
Проверено: WAV-клип (440 Гц, 1.04 с) и MIDI-тон (Gervill) приходят в WebSocket с правильной частотой/уровнем.
MP3 (javazoom), AMR-NB и SMF-MIDI проходят тот же путь и дают PCM (`tools/audit/probe.mjs`, сценарий `media`; AMR — синтетический битовый поток). Не проверено: звук игр с большим количеством одновременных голосов, настоящие AMR/MP3 из игр.
