Поддерживай коллекцию из десяти скинов J2ME Web. Ассеты: `apps/web/public/phones/<id>/`; контракт: `apps/web/public/phones/README.md`, параметры: `config.json`. Используй существующие React `PhoneSkin`, переключатель моделей и таблицу `packages/protocol/src/phones.ts`. В Advanced корпус выбирается отдельно от профиля/разрешения эмуляции.

Обязательно два режима для каждого телефона: `views.full` — весь корпус, `views.screen` — увеличенная верхняя часть телефона с экраном (`zoom.webp`). Используй размеры и `screenRect` выбранного вида; Canvas с настоящим framebuffer KEmulator размещай под body, optional glass сверху. Сохраняй пропорции, при несовпадении framebuffer добавляй поля. E71 — вертикальный корпус с горизонтальным дисплеем 320×240. Zoom не меняет разрешение игры и не перезапускает MIDlet.

В full-виде используй `buttons`/`hitboxes.svg` и `keyMappings`; null-функции не превращай в вымышленные коды. Поддержи pointer capture, удержание, мультитач и release на cancel/blur/смене модели/вида. В screen-виде кнопки корпуса отсутствуют: оставь внешнюю экранную клавиатуру, клавиатуру ПК и gamepad. Состояние ввода общее, смена вида освобождает удержание.

В production `/phones` показывает каталог десяти моделей. Сравнение видов и отладка screen/hitboxes находятся в dev-модуле и доступны в Developer Mode dev-сборки. Проверь масштабирование, E71 QWERTY, одновременные нажатия, отсутствие залипания и настоящий MIDlet. Для 5800/S5230 сохрани сенсорный Canvas и внешнюю клавиатуру в обоих видах, не добавляй вымышленные цифровые клавиши на корпус. Запусти `python3 tools/phones/validate_assets.py`, сборку и `node tests/e2e/phone-expansion.mjs`; dev-геометрия проверяется `npm run test:e2e:dev`. Статус графики review-draft и ограничения README/references.md сохраняются: техническая валидация не означает историческую сертификацию.
