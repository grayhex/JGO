# Symbian S60 и N-Gage (экспериментально)

JGO умеет запускать игры Symbian S60 и N-Gage 1.0/2.0 вторым ядром эмуляции — **EKA2L1**. Это отдельный необязательный контейнер `jgo-symbian`:
без него JGO работает как раньше, а ядро J2ME (KEmulator) не затронуто ни в поведении, ни в коде запуска.

> **Статус: экспериментально, подтверждено частично.** Всё, что можно проверить без прошивки и без настоящей игры, проверено (в том числе на реально
> собранном EKA2L1). Запуск настоящей N-Gage-игры в браузере **здесь не проверялся**: у разработчика интеграции нет ни прошивки, ни образа игры, а
> класть их в репозиторий или образ нельзя. Раздел [«Что проверено, что нет»](#что-проверено-что-нет) перечисляет это поимённо.

## Как это устроено

```
 браузер ──WebSocket (тот же протокол, что у J2ME)──► JGO (app) ──HTTP + токен──► jgo-symbian
                                                                                  ├─ agent.mjs (порт 8766, единственный открытый порт)
                                                                                  ├─ Xvfb :99 + Mesa llvmpipe (программный OpenGL)
                                                                                  ├─ PulseAudio, null-sink «jgo_sink»  ← звук снимается с его monitor
                                                                                  └─ EKA2L1 (Qt) --debug-control-port, только 127.0.0.1
```

- `apps/api/src/emulator.ts` — интерфейс `EmulatorAdapter`. `KEmulatorAdapter` (J2ME) и `Eka2l1Adapter` (Symbian/N-Gage) реализуют его; `Session` и
  WebSocket-поток от выбора ядра не зависят. Поле `GameMeta.platform` (`j2me`, `symbian`, `ngage`, `ngage2`) выбирает ядро автоматически:
  `j2me` → KEmulator, остальные → EKA2L1 (`backendOf` в `packages/protocol`). `SessionStatus.backend` сообщает, какое ядро работает.
- `apps/api/src/eka2l1/adapter.ts` — установка пакета, запуск игры, клавиши, тач, пауза, кадры и звук. Кадры берутся опросом `GET /v1/screenshot`
  (PNG → RGBA → тот же кадр WebSocket, но с собственным размером `width×height`), звук — снимком виртуальной звуковой карты (`parec`).
  Это **временный захват**, ядро EKA2L1 не изменялось.
- `symbian/agent/agent.mjs` — маленький сервис без зависимостей (Node 22). EKA2L1 слушает управление на `127.0.0.1` и **не имеет аутентификации**,
  поэтому наружу выставлен только агент: токен, загрузка файлов, жизненный цикл экземпляра и список разрешённых маршрутов `/v1/*`
  (`symbian/agent/policy.mjs`).

## Платформы в библиотеке

| platform | Файл | Ядро |
|---|---|---|
| `j2me` | `.jar` (+ `.jad`) | KEmulator |
| `symbian` | `.sis`, `.sisx` | EKA2L1 (тип установки `sis`) |
| `ngage2` | `.n-gage` | EKA2L1 (`ngage2`, копируется в `E:/n-gage`) |
| `ngage` | `.zip` — дамп карточки N-Gage 1.0 (внутри `system/apps`) | EKA2L1 (`ngage`: каталог карточки) |

Игры добавляются перетаскиванием в окно, кнопкой «Добавить» или сканированием папки (`.sis`, `.sisx`, `.n-gage` находятся рекурсивно). `.zip` сам по
себе ничего не говорит о платформе: при сканировании папки он **игнорируется**, а при загрузке принимается как дамп карточки N-Gage 1.0 (`platform=ngage`
по умолчанию; поле формы `platform` позволяет указать другое). Размер пакета ограничен `MAX_SYMBIAN_PACKAGE_MB` (512 МБ), проверяется расширение, соответствие платформе и магия `PK`
для zip; дубликаты определяются по SHA-256.

## Установка

1. Включите контейнер (нужен токен — общий секрет между JGO и службой):

   ```bash
   export SYMBIAN_TOKEN=$(openssl rand -hex 24)
   ```

   ```bash
   docker compose -f compose.yaml -f compose.symbian.yaml up -d
   ```

   Образ `ghcr.io/grayhex/jgo-symbian` публикует CI после слияния в `main`. Собрать самому (30–60 минут: компилируются EKA2L1 и FFmpeg):

   ```bash
   docker compose -f compose.yaml -f compose.symbian.yaml -f compose.symbian.build.yaml build jgo-symbian
   ```

2. Откройте *Settings → Symbian (experimental)*: там видны состояние службы и версия EKA2L1.
3. Добавьте **свою** прошивку (ROM + RPKG либо архив). Файлы потоком уходят в службу, не сохраняются в JGO и не попадают в образ; установка занимает минуты.
4. Загрузите игру и нажмите «Играть».

Прошивки и ROM не входят ни в репозиторий, ни в образ, ни в CI: в `.gitignore` и в `Dockerfile` их нет, а `compose.symbian.yaml` хранит их только в томе
`jgo-symbian-data`. Откуда взять прошивку законно — на вашей совести (например, дамп собственного телефона).

## Изоляция и ограничения

| Что | Как |
|---|---|
| Сеть | `jgo-symbian` в отдельной `internal`-сети `symbian`, общей только с `app`. Маршрута наружу нет; Токен не передаётся в окружение JVM с MIDlet (`kemulator/adapter.ts`), а без токена служба отвечает только на `/agent/ping`. Оговорка: это не граница безопасности против враждебного кода в JVM того же пользователя (как и для `AUTH_TOKEN`, см. [SECURITY.md](SECURITY.md)). |
| Управление EKA2L1 | Только `127.0.0.1` внутри контейнера, запросы с заголовком `Origin` он отклоняет. Агент пропускает фиксированный список маршрутов; закрыты `/v1/files` (запись/чтение файлов хоста), `/v1/config`, `/v1/card`, установка и удаление устройств в обход агента, `DELETE /v1/apps`. `POST /v1/apps` — только с путями внутри каталога `in/` текущего экземпляра и с известным типом. |
| Файлы | Имена проверяются (`safeName`); загрузки пишутся во временный `.part` с лимитом размера «на лету» и переименовываются; архив карточки N-Gage проверяется (`unzip -Z1`, пути без `..`, не более 20 000 файлов и 4 ГБ распакованного). |
| Сессии | Один экземпляр EKA2L1 одновременно (`409 busy` на второй). Каждый запуск получает собственный каталог данных `/data/run/<id>` (`XDG_DATA_HOME`, `HOME`), который удаляется при остановке. Прошивка (`roms`, `drives/z`) подключается жёсткими ссылками из общей базы и никогда не изменяется. |
| Сохранения | Диски игры `C:` и `E:` лежат в `/data/saves/<ключ>/`, где ключ — первые 32 hex `sha256(owner\0gameId)`. Другая игра получает другой каталог; «Удалить с сохранениями» в JGO удаляет и их. |
| Ресурсы | Контейнер: `read_only`, `cap_drop: ALL`, `no-new-privileges`, `cpus` (2), `mem_limit` (3 ГБ), `pids_limit`, `tmpfs /tmp`, `shm_size`. Агент: `MAX_INSTANCE_SECONDS` (2 ч), `MAX_PACKAGE_BYTES`, `MAX_FIRMWARE_BYTES`. Процесс запускается отдельной группой и убивается целиком. |
| Токен | `AGENT_TOKEN` ≥ 16 символов, сравнение за постоянное время; только `/agent/ping` (для healthcheck) открыт. |

## Управление

Кнопки J2ME-кодов отображаются на клавиши EKA2L1 (`apps/api/src/eka2l1/keymap.ts`): стрелки, `ok`, левая/правая софт-клавиши, `clear`, `*`, `#`, `0–9`.
Тач (`pointerEvent`) идёт в `/v1/input/touch` в координатах кадра; несколько пальцев различаются по `id`. Неизвестные клавиши отбрасываются, а не
угадываются. Пауза → `/v1/emulator/pause|resume`.

**Не поддерживается** (с одноразовым сообщением в журнале сессии): скорость игры, ввод текста, команды меню J2ME, запросы разрешений, скриншоты/запись
кадров средствами плеера работают как обычно, а «Файлы игры» (JSR-75) и профиль телефона/куча — только для J2ME и скрыты для остальных платформ.

## Что проверено, что нет

**Проверено** (ноябрь 2026, EKA2L1 `master-e04eb03`, Ubuntu 24.04, x86-64):

- API управления EKA2L1 (`/v1`) вышел в `master` 31 октября 2026 (PR #970) и **не входит ни в один релиз** — собирать нужно из исходников; образ закреплён
  на коммите `e04eb030653d185483a44f0394d42a319ad334f2`. Смена коммита требует повторной проверки.
- Сборка Qt-фронтенда из исходников (Release, Ninja) проходит; нужны `libsdl2-dev` и Qt6; FFmpeg собирается из исходников (долго).
- Настоящий бинарник под Xvfb (программный GLX 4.5, llvmpipe) открывает порт управления, отвечает на `GET /v1`, `/v1/status`, `/v1/capabilities`, `/v1/keys`,
  `/v1/devices` (пусто), `/v1/apps` (`409 no_device`), `/v1/screenshot` (`409 no_screen`), отклоняет запросы с `Origin` (`403`) и
  отвечает `422 install_failed` на неверный архив прошивки (также как фоновое задание `?async=1`).
- **Находка:** без установленного устройства Qt-фронтенд показывает *модальное* окно «No device installed» **до** запуска порта управления, так что
  на чистом каталоге данных API недоступен. Агент пишет в `$XDG_CONFIG_HOME/EKA2L1/EKA2L1.conf` ключ `disableNoDeviceInstallNotify=true`
  (кнопка «Don't show this again» самого окна) — после этого порт отвечает. Проверено на реальном бинарнике.
- Агент + реальный EKA2L1: токен, `412 no_firmware`, режим обслуживания, прокси `/v1/status`, `403` на `/v1/files`, остановка экземпляра
  (тест `agent with the real EKA2L1`, запускается при `EKA2L1_BIN=…/eka2l1_qt`; в CI — шаг smoke образа).
- Цепочка звука PulseAudio: null-sink `jgo_sink` + `parec --device=jgo_sink.monitor` от пользователя без root принимает синтетический тон без искажений.
- Агент + **поддельный** EKA2L1 (`tests/fixtures/fake-eka2l1`, он честно подписан как подделка) + API + WebSocket: загрузка и установка прошивки заданием,
  412 до установки, лимиты размера (413), установка пакета, кадры собственного размера, звук, клавиши по порядку, тач с `id`, запоминание установленного
  приложения, раздельные диски игр, удаление сохранений, 403 для опасных маршрутов, одновременно один экземпляр. Это проверяет **сторону JGO**, но ничего не
  говорит о поведении настоящего эмулятора с настоящей игрой.
- Существующие тесты (`npm test`, интеграционные и e2e KEmulator) проходят без изменений.

**Не проверено** (не выдаётся за работающее):

1. Запуск настоящей игры N-Gage/S60 с настоящей прошивкой: **PoC «одна N-Gage-игра в браузере» здесь не продемонстрирован**. Нет ни прошивки, ни игры.
2. Что реально делает `POST /v1/devices` с реальной прошивкой (время, поля ответа, формат архива `.7z/.rar`), и что делает `DELETE /v1/devices/{x}`.
3. Раскладка каталога данных после установки прошивки (`roms/`, `drives/z|c|e`): агент рассчитывает на неё для жёстких ссылок и сохранений
   (`INSTANCE_SHARED_DIRS`, `INSTANCE_PERSIST_DIRS` настраиваются). Если она иная, сохранения не переживут перезапуск.
4. Что приложение находится по uid после установки и что `POST /v1/apps/{uid}/launch` стартует именно его (агент берёт uid из ответа установки, а при пустом
   ответе — единственное несистемное приложение; при нескольких откажется, а не угадает).
5. Звук реальной игры: путь EKA2L1 (cubeb) → PulseAudio → `parec` не проверен; задержка и синхронность с картинкой не измерены.
6. Скорость: программный OpenGL на CPU — вероятно, медленно для 3D-игр N-Gage. Опрос PNG даёт до ~20 кадров/с на маленьких экранах, больше — не измерялось.
7. N-Gage 1.0: карточка передаётся каталогом (в API управления есть только этот вариант); образы в других форматах придётся распаковать самостоятельно.
8. Тач/клавиши реальных игр, поведение при `crashed` и паника эмулятора, а также `screen-mode` и поворот экрана.
9. ARM и не-x86-64 хосты, Windows/macOS: образ рассчитан на Linux x86-64.

## Известные ограничения

- Один экземпляр на службу, значит один Symbian-сеанс за раз (J2ME-сессии параллельно допускаются, как раньше).
- «Остановить» сначала закрывает приложение (`DELETE /v1/session`), затем завершает процесс; если EKA2L1 не выходит за ~4 с, он убивается (`SIGKILL`).
  Сохраняйте прогресс средствами самой игры.
- Скины телефонов косметические: картинка занимает размер, который рисует игра.
- Время жизни API управления: он новый и меняется; агент ссылается только на маршруты, прочитанные в исходниках (`src/emu/control`).
- Лицензии: EKA2L1 — GPL-2.0 (отдельный контейнер, не линкуется с JGO); прошивки и игры принадлежат их правообладателям.
