# HTTPS в MGO

Docker gateway принимает HTTPS на порту **8443**, перенаправляет HTTP с **8080** и передаёт WebSocket через **WSS**. Приложение и эмуляторы остаются в закрытых сетях. Большие файлы проходят потоково с прежними лимитами.

## Сертификат для локальной сети

При первом запуске gateway создаёт локальный сертификат и ключ в отдельном постоянном томе `mgo-tls`. Они сохраняются при перезапуске и обновлении. Для вашего адреса задайте SAN **до первого запуска**, например в `.env`:

```dotenv
MGO_HTTPS_PORT=8443
MGO_TLS_SAN=DNS:mgo.home,IP:192.168.1.50
```

Откройте `https://192.168.1.50:8443`. Локальный самоподписанный сертификат не становится публично доверенным автоматически: установите доверие к `server.crt` на клиентских устройствах либо используйте сертификат своего домена. Значения по умолчанию покрывают только `localhost` и `127.0.0.1`.

Получить публичную часть сертификата:

```sh
docker compose cp gateway:/certs/server.crt ./mgo-server.crt
```

Приватный `server.key` остаётся на сервере. Изменение `MGO_TLS_SAN` не перезаписывает существующую пару: новый сертификат нужно выпустить отдельно и заменить вместе с ключом.

## Доверенный сертификат домена

Создайте каталог с файлами `server.crt` (полная цепочка) и `server.key`, доступными процессу gateway, и укажите его:

```dotenv
MGO_TLS_CERTS=/volume1/docker/mgo/certs
MGO_HTTPS_PORT=443
```

Gateway использует существующую пару и не заменяет её. После продления сертификата перезапустите gateway. Для автоматического выпуска/продления можно использовать ваш NAS или внешний reverse proxy; сам MGO не запрашивает сертификаты Let's Encrypt.

Если внешний HTTPS-прокси обращается к gateway по HTTPS, задайте проверку сертификата upstream. Если он обращается непосредственно к `app:8080` в общей закрытой сети, передавайте `Host`, `X-Forwarded-Proto: https`, `Upgrade` и `Connection`; не публикуйте порт `app` наружу. Основной compose уже задаёт `TRUST_PROXY=1`, а gateway сам устанавливает forwarded-заголовки. Auth-cookie на HTTPS получает `Secure`.

## Порты и тестирование

`MGO_PORT` — входящий HTTP-порт перенаправления; `MGO_HTTPS_PORT` — внешний HTTPS-порт. При публикации нестандартного порта значение `MGO_HTTPS_PORT` должно совпадать с ним, чтобы Location у HTTP-перенаправления был правильным.

```sh
docker build -f runtime/Dockerfile --target gateway -t mgo-gateway:verify .
docker pull node:22-alpine
npm run test:https
```

Тест создаёт временные контейнеры/том и проверяет доверенную цепочку с локальным сертификатом, 308, WSS, потоковую загрузку 70 МБ и сохранение сертификата при перезапуске. Проверка TLS не отключается.
