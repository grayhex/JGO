# Интерфейс, звук и диагностика MGO

## Исправления по реальному отчёту Pathway to Glory

В предоставленном отчёте игра работала на `NEM-4`, кадры приходили, но `audioBytes` оставался нулём. EKA2L1 сообщал `Error trying to initialize cubeb stream` и `Failed to start audio output stream`.

Служба теперь задаёт один явный Unix-сокет PulseAudio, выход `mgo_sink` и источник `mgo_sink.monitor` для EKA2L1 и `parec`. Разные HOME экземпляров не меняют адрес аудиосервера. Пустые `PULSE_*` больше не передаются; запуск службы проверяет sink/source и останавливается с журналом, если аудиосервер не поднялся. Ошибки `parec` и раннее завершение аудиопотока попадают в диагностику. Клиент собирает полные стереокадры PCM из произвольных HTTP-чанков, чтобы не передавать обрывки сэмплов в AudioWorklet. Там же видны состояние PulseAudio, число потоков и полученные PCM-байты. Ненулевые байты сами по себе могут содержать тишину.

Проверка без прошивки: настоящий PulseAudio принимает тестовый тон из процесса с отдельным HOME, монитор отдаёт PCM, тест проверяет ненулевую амплитуду. Это не заменяет повторный запуск самой игры на вашей прошивке. Пересоберите **службу mgo-symbian**, а не только app.

В отчёте также установлен N95 8GB `RM-320`; это отдельный профиль с тем же скином семейства N95. При отсутствии явной привязки игры несовместимое умолчание N70 не перевешивает поколение SIS9. Если подходящая прошивка одна, выбирается она; если несколько — требуется выбор. Явная привязка к N70 не игнорируется и по-прежнему даёт точную ошибку несовместимости. Совместимое поколение пакета не гарантирует совместимость конкретной игры с EKA2L1.

Выбор нативного телефона в `/phones` сохраняет соответствующую **установленную** прошивку и профиль. Для отсутствующей модели запрашивается её профиль и отображается предупреждение; под её изображением не запускается другой ROM. При нескольких вариантах одной модели плеер предлагает выбрать прошивку. Изображение не устанавливает прошивку.

Сообщение «служба занята» не показывается для собственного запущенного/запускающегося сеанса. Занятость другим сеансом или firmware job продолжает блокировать новый запуск.

## Settings

Вкладки поддерживают deep links, клавиши стрелок/Home/End и сохраняют несохранённые формы при переключении. System опрашивается последовательно раз в пять секунд: CPU, память и лимиты cgroup, диск, версии, сессии, кадры, PCM и скачивание диагностики. При недоступности измерения выводится «—».

В Game library настраиваются три каталога:

- Java ME: `.jar` и `.jad`;
- N-Gage: `.zip` оригинальных карточек и `.n-gage` второго поколения;
- Symbian: `.sis` и `.sisx`.

Исходники читаются без изменения. Источники файлов имеют независимые пространства имён; одинаковые имена в разных каталогах не смешиваются. Пустой каталог сам по себе не доказывает удаление коллекции. Старая настройка общего каталога читается; при сохранении каталога Java через новый интерфейс общий путь снимается. Настройки и сохранения уже импортированных игр остаются.

Default phone отдельно задаёт Java ME и три нативные платформы. Нативное значение «Автоматически» следует установленной прошивке; выбор телефона по умолчанию применяется к новым играм вместе с профилем прошивки. Единственный установленный вариант семейства N95 8GB сохраняет собственный RM-320; если выбранной модели нет, игра сообщает о недостающей прошивке. Реальные firmware defaults можно изменить в Settings → Symbian.

## All About Symbian

Для оригинального N-Gage используется [каталог All About Symbian](https://allaboutsymbian.com/n-gage-games/original/). MGO разбирает выпущенные игры, сопоставляет точное нормализованное название и загружает сведения/обложку только для игр библиотеки. Неоднозначное совпадение не выбирается автоматически. Другие платформы не получают чужие метаданные.

Обложки, жанр, издатель, год, оценка, мультиплеер и код продукта хранятся в `/data/aas`. Кеш обновляется через 30 дней; ручное обновление — Settings → Game metadata. Отказ источника не удаляет сохранённые сведения. Назначенные пользователем названия/жанры имеют приоритет. В карточке и сведениях есть ссылка на источник; тексты описаний целиком не копируются.

Браузер не обращается к стороннему сайту. В compose app получает фиксированный `AAS_PROXY_URL=http://gateway:9090`; этот порт не публикуется, разрешены только страницы и изображения каталога AAS. Общего доступа в интернет для эмулятора это не добавляет. При запуске вне Docker сервер может обращаться к AAS напрямую. Метаданные не содержат игр или прошивок.

## Обновление установки и нейминг

Образы, compose project, тома, CLI, systemd и документация используют MGO. Перед переходом остановите игры, сохраните резервную копию `/data` и подключите существующие данные к новым именам томов/путей. Docker сам не переносит содержимое между томами после смены project/volume name. В `/data` сохраняются SQLite, настройки, игры, сохранения и кеш; переимпортировать их для нового имени приложения не требуется. Том прошивок службы также нужно перенести или подключить под прежним физическим именем через override compose.

HTTPS и сертификаты: [HTTPS.md](HTTPS.md). Сборка для проверки до выпуска образов: `docker compose -f compose.yaml -f compose.build.yaml up -d --build`.
