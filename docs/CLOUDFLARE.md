# Cloudflare: оценка готовности (ничего не развёрнуто)

Ничего в Cloudflare не создавалось и не деплоилось; разрешения на деплой нет. Ниже — оценка по замерам и документации
(лимиты/цены прочитаны 2026-10-30 с developers.cloudflare.com/containers/{platform-details/limits,pricing}).

## Целевая схема

* Workers Static Assets — `apps/web/dist`.
* Worker + Durable Object (класс из `@cloudflare/containers`) — на сессию: запускает контейнер, проксирует `/api/sessions/:id/stream`
  (WebSocket) в контейнер, хранит владельца/таймеры.
* Container — образ `runtime/Dockerfile` (JVM + kem-adapter + Node API, один пользователь/сессия).
* R2 — JAR, иконки, **RMS** (контейнерный диск эфемерный: синхронизировать `saves/` в R2 при останове и по таймеру).
* D1 — метаданные библиотеки (вместо SQLite).
* Клиентский код и API не меняются; различается только слой хранилища (`Library`) и запуск контейнера.

`infrastructure/cloudflare/` содержит **набросок** `wrangler.jsonc` и Worker — не проверялся и не деплоился.

## Инстансы и стоимость (по замерам)

Инстансы: lite 1/16 vCPU 256 MiB · basic 1/4 vCPU 1 GiB · standard-1 1/2 vCPU 4 GiB · standard-2 1 vCPU 6 GiB · standard-3 2 vCPU 8 GiB · standard-4 4 vCPU 12 GiB.
Тариф Workers Paid ($5/мес). Тарификация: память и диск — по выделенному, **CPU — по фактической загрузке**, шаг 10 мс.
Ставки: память $0.0000025/GiB·с, CPU $0.000020/vCPU·с, диск $0.00000007/GB·с; включено 25 GiB·ч, 375 vCPU·мин, 200 GB·ч в месяц.

Замеры локально (4 vCPU, без GPU), тестовые MIDlet:

| Сцена | JVM RSS | CPU всего процессами сессии | Комментарий |
|---|---|---|---|
| 2D 240×320 @30 | ≈94 MB | ≈6 % одного vCPU | deflate-кадры ≈1.3 Мбит/с |
| M3G (1 треугольник, llvmpipe) | ≈207 MB | ≈16 % vCPU | реальные 3D-игры будут тяжелее — **не измерено** |

Грубая оценка для 2D, `standard-2` (1 vCPU / 6 GiB) на час игры: память 6 GiB × 3600 × $0.0000025 ≈ **$0.054**, диск 12 GB × 3600 × 7e-8 ≈ $0.003,
CPU 0.06 vCPU × 3600 × $0.00002 ≈ $0.004 → порядка **$0.06/час**, где доминирует выделенная память; `basic` (1 GiB) дал бы ≈$0.01/час, но
память Node+JVM+Xvfb впритык (измерено ≈240 MB Node + 100–210 MB JVM + Xvfb), а 1/4 vCPU мало для M3G на llvmpipe. Выбор
инстанса по реальным играм не делался — нужны замеры на настоящих тайтлах (особенно 3D).

## Что проверено / что нет (чеклист из задания)

| # | Пункт | Статус |
|---|---|---|
| 1 | JVM и native-библиотеки | ✔ в Docker (ubuntu:24.04, OpenJDK 21, LWJGL natives) — но не в самом Cloudflare |
| 2 | FIFO, mmap, Mesa, Xvfb | ✔ в Docker (non-root, read-only rootfs, tmpfs `/dev/shm`); в Cloudflare не проверялось. Weston не используется — Xvfb + Mesa llvmpipe подтверждены и проще |
| 3 | 2D и 3D без GPU | ✔ 2D; ✔ M3G на llvmpipe (простая сцена); тяжёлые игры не проверялись |
| 4 | Захват/передача звука | ✔ собственный Java Sound mixer → PCM по WS (без PulseAudio/PipeWire) |
| 5 | Холодный старт контейнера | ✘ не измерен в Cloudflare. Локально: сессия → первый кадр ≈0.75 с, запуск контейнера не включён |
| 6 | Жизненный цикл | ✔ логика (лимиты, idle, graceful stop) в API; DO-управление — не реализовано |
| 7 | RMS перед завершением | ✔ локально (graceful SIGTERM → `stopAll`), ✔ том переживает рестарт; выгрузка в R2 — не реализована |
| 8 | CPU/RAM/стоимость | частично: см. выше |
| 9 | Стабильность WebSocket | ✔ локально (переподключение, кэш кадра, отпускание клавиш); через Worker→DO→Container не проверялось |
| 10 | Недоверенный код | ✔ Docker-меры (SECURITY.md); у Cloudflare изоляция на уровне VM на контейнер — не проверялось, но это сильнее общего хоста |

## Альтернатива: Linux VM (Proxmox) + Cloudflare Tunnel

`docker compose up` на VM; `cloudflared tunnel` на `http://gateway:8080` (WebSocket поддерживается). Frontend можно отдавать с VM
тем же nginx либо с Workers Static Assets (тогда API на другом origin → `ALLOWED_ORIGINS`, cookie `SameSite=Strict` не подойдёт —
проще держать UI и API на одном домене). Перед открытием наружу обязателен `AUTH_TOKEN`, Cloudflare Access — рекомендуется. Постоянное хранилище — том VM или R2.
Это самый быстрый путь к публичному доступу и он не требует переписывания: **рекомендация — начать с него**, а Containers
рассматривать после замеров на реальных играх и холодного старта.

## Следующий шаг

Замерить на реальных тайтлах CPU/RAM (2D и 3D) и выбрать инстанс; затем (с разрешением владельца аккаунта) поднять тестовый Worker+Container
с образом из `runtime/Dockerfile` и измерить холодный старт и стабильность WS.
