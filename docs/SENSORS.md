# Датчики и геолокация из браузера: исследование (issue #17)

**Решение: сейчас не делаем.** Ниже — что выяснено, почему, и каким образом это можно будет сделать, если условия изменятся.
Всё перечисленное проверено по исходникам KEmulator (`9ec1005`) и запуском; «[R]» — проверено запуском.

## Как ядро получает данные

| Что | Как устроено | Где |
|---|---|---|
| JSR-256 (Sensor API) | находятся **два** датчика с описанием `orientation` (acceleration, контексты `device` и `user`, модель `ACCM01`) **[R]** | `emulator/sensor/SensorRegistry.java:29-40` |
| Источник значений | **внешний** OpenIntents SensorSimulator по TCP: хост и порт **зашиты в код** — `localhost:8010` | `SensorSimulatorClient.connect()` |
| Протокол | текстовый, построчный. Сервер при подключении присылает `SensorSimulator`; клиент пишет `enableSensor()` / `disableSensor()` / `readSensor()`, следующей строкой — имя датчика; ответ `readSensor` — число N и N строк с float; ошибки — строки `throw IllegalArgumentException` / `throw IllegalStateException` | `SensorSimulatorClient` |
| Частота | поток опроса каждые 30 мс на датчик (≈ 33 Гц) | `SensorSimulator.run()` |
| Без сервера | подключение не удаётся, датчик «найден», значения остаются нулевыми **[R]** | аудит, `tools/audit/results.json` |
| JSR-179 (Location) | не внешний источник, а **зашитый список** координат (1,1), (2,2), (3,4)… | `com/nokia/mid/impl/isa/location/EmulatedLocationProvider` |

## Почему не делаем

1. **Игра не может дойти до сервера на хосте.** Каждая игра запускается в собственном сетевом пространстве имён без интерфейсов
   (`KEM_LAUNCH_WRAPPER=unshare --user --map-current-user --net --`). Проверено: из такого пространства `127.0.0.1:8010` недоступен
   (`Network is unreachable`) **[R]**. Включение сети для датчиков сняло бы главную защиту (игра — недоверенный код).
2. **Браузер даёт данные только на подходящей странице.** `DeviceMotionEvent` и `Geolocation` требуют защищённого контекста (HTTPS или localhost);
   JGO по умолчанию открывают по `http://<IP контейнера>:8080`. На iOS нужно ещё явное разрешение пользователя, на настольных
   компьютерах акселерометра обычно нет совсем.
3. **Нужен патч ядра.** Адрес сервера зашит, поэтому подменять приходится сам клиент (`SensorSimulatorClient`), а не настраивать его.
4. **Мало игр, которым это нужно.** Игры 2005–2012 годов с акселерометром — единицы, а клавиатурное управление в них почти всегда есть.
5. **Выигрыш для Location — ещё меньше**: у игр нет сетевой привязки к месту, а зашитые координаты для них достаточны.

## Как делать, если решим (набросок)

* Патч ядра: заменить транспорт `SensorSimulatorClient` с TCP на Bridge. Новые пакеты (в стиле существующих, ASCII-строки на вход, бинарные на выход):
  * из ядра: `G 1 <имя>` / `G 0 <имя>` — датчик включён/выключен (клиент запрашивает разрешение браузера только тогда, когда игра действительно открыла датчик);
  * в ядро: `G <имя> <x> <y> <z>` — последнее значение; `readSensor` отдаёт его без сети.
* Node/protocol: событие `sensor` (вкл/выкл) и клиентское событие `sensor-data`, не чаще 30 раз в секунду на датчик, значения ограничены диапазоном.
* UI: запрос `DeviceMotionEvent.requestPermission()` по клику, преобразование осей телефона в оси JSR-256 (ориентация экрана учитывается), индикатор «датчик занят».
* Location: отдельный пакет и кнопка «передать моё местоположение» (по клику, не автоматически; координаты не сохраняются).
* Условия, при которых имеет смысл начинать: поддерживаемый HTTPS-режим установки и конкретная игра из коллекции, которой без датчика нельзя пройти.

## Критерии приёмки будущей реализации

- [ ] Проба `tools/audit/probe.mjs apis` получает от датчика ненулевые значения, переданные клиентом.
- [ ] Без разрешения браузера датчик остаётся «найденным», но тихим; игра не падает.
- [ ] Игра по-прежнему не имеет сетевого доступа (проверка `jgo doctor` и `tests/integration`).
- [ ] Частота и диапазон ограничены на сервере; тест на выход за границы.
